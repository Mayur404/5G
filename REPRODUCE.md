# Reproducing the CARE study

This guide covers everything needed to install the project, check it, regenerate every table and figure in the paper, and rerun the full experiment from scratch.

Paper: `paper/main.pdf` (LaTeX source in `paper/`, the same files as `Overleaf_Source.zip`).

Authors: Mayur Raju (24BCS073), Naramsetti Charan Raj Gupta (24BCS083), P Gnandeep (24BCS095), P Sanjay (24BCS100), S Sudharsan Reddy (24BCS130), Shaik Moiz (24BCS133). Department of Computer Science and Engineering, Indian Institute of Information Technology Dharwad.

## 1. What is in the submission

| Path | Contents |

## 2. Data

**All data are synthetic.** No external dataset is downloaded or required. Every trajectory, traffic sample, forecast and radio outcome is generated by the simulator (`src/proran/simulator.py`) from a seed. The seed sets never overlap:

| Role | Seeds |
| --- | --- |
| Forecaster training | 3000–3023 |
| Forecaster validation | 4000–4005 |
| Calibration | 4100–4119 |
| CARE training (replica *r* ∈ {101, 102, 103}, episode *e* = 0, 1, …: seed 20000 + 1000·(*r* − 100) + *e*) | 21000–21239, 22000–22239, 23000–23239 |
| Rule tuning and ensemble replica selection | 5000–5009 |
| Held-out test | 9000–9019 |
| Network initialization (CARE replicas) | 101, 102, 103 |
| Forecaster weight initialization | 73 |

All methods evaluated on one seed share the same mobility, traffic, forecast and radio random streams (`common_radio_stream=True`), so comparisons are paired.

## 3. Install

Tested with **Python 3.12.10** and NumPy 2.2.6 on Windows 11. Any Python 3.10 or newer should work.

**Windows (PowerShell), from the project folder:**

```powershell
.\bootstrap.ps1        # creates .venv and installs everything below
```

**Linux / macOS (or manually on Windows):**

```sh
python3 -m venv .venv
. .venv/bin/activate                 # Windows: .\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt -r requirements-web.txt -r requirements-dev.txt
python -m pip install -e . --no-build-isolation
```

| File | Packages | Needed for |
| --- | --- | --- |
| `requirements.txt` | numpy 2.2.6, matplotlib 3.10.3 | simulation, training, figures |
| `requirements-web.txt` | Flask 3.1.1, waitress 3.0.2 | web lab only |
| `requirements-dev.txt` | pytest 8.4.0, ruff 0.14.0 | tests and lint |

No GPU is used. The learner is written in plain NumPy.

A container is also provided: `docker build -t proran-ui . && docker run --rm -p 8080:8080 proran-ui`.

## 4. Check the installation (about 15 s)

```sh
python -m pytest -q
```

This runs 107 tests: simulator accounting, reservation lifecycle, calibration, the neural forecaster, the web API, and two paper checks. The paper checks confirm that every result in `paper/main.tex` comes from a generated macro and that `paper/` matches `results/care/` byte for byte.

## 5. Regenerate the paper's tables, figures and numbers (about 10 s)

From the saved per-seed runs, without any simulation:

```sh
python -m proran.care_experiment report

```

## 6. Re-evaluate the saved models (about 6 min on 16 threads)

```sh
python -m proran.care_experiment tune evaluate report
```

This retunes the 45 threshold rules on seeds 5000–5009, selects replicas, and evaluates all 12 methods plus the sweeps and mechanism ablations on test seeds 9000–9019 (1,380 runs). On the reference machine the results are bit-identical to the files shipped in `results/care/`. Only the wall-clock `seconds` column of `runs.csv` changes.

## 7. Rerun the full study from scratch (about 47 min on 16 threads)

```sh
python -m proran.neural                 # optional: retrain the forecaster (writes results/deep/)
python -m proran.care_experiment        # calibrate, train, tune, evaluate, report
python scripts/build_submission.py sync
```

The stages can also be run one at a time: `calibrate`, `train`, `tune`, `evaluate`, `report`.

- `calibrate` fits the logistic confidence model on seeds 4100–4119 → `results/care/calibrator.npz`, `calibration.json`.
- `train` trains, for each price λ ∈ {0.25, 1, 4, 16} and replica seed ∈ {101, 102, 103}: CARE (fitted Q, 240 episodes), CARE-PPO (160 episodes), CARE without calibration (λ = 1), and CARE-PPO with on-policy wait (λ ∈ {1, 16}) → `results/care/models/`.
- `tune`, `evaluate` and `report` are as above.

**Verified end to end (18 Nov 2026):** a fresh clone from GitHub, a new virtual environment and `python -m proran.care_experiment` (46 min 47 s on 16 threads) reproduced the calibrator, all 33 trained models (byte-identical), the tuning choices, all 1,380 held-out runs, the statistics, tables and every paper macro exactly. Only the wall-clock `seconds` column differs. Retraining the forecaster (`python -m proran.neural`, 38 s) gives weights within 3×10⁻¹⁵ of the shipped ones (floating-point round-off) and the same validation metrics. The pipeline always uses the shipped forecaster, `results/deep/predictor.npz`.

On other platforms or BLAS builds, floating-point summation order can differ slightly, which changes trained weights and can therefore change small digits of the results.

## 8. Main settings and baseline configurations

All defaults live in `src/proran/config.py` (`SimConfig`), `src/proran/care.py` (`CareConfig`) and the `BASE` configuration at the top of `src/proran/care_experiment.py`. Table II of the paper lists them. In short:

- **Simulation:** 4 cells × 60 RB, 32 UEs, 100 ms intervals, 320 intervals per run, outage 3 intervals after a failed admission, preparation delay 1 interval, floor-protected activation, retiming of pending holds, up to 32 decisions per interval.
- **CARE:** Q-network 17–64–64–10 (tanh), Adam lr 1e-3, minibatch 512, 6 epochs × 2 target iterations every 4 episodes, γ = 0.98, ε annealed 1 → 0.05 over the first 75 % of 240 episodes, ensemble of 3 replicas, reward weights w = (1, 2, 0.5) for (eMBB, uRLLC, mMTC), QoS value q = 4.
- **Baselines** (`care_experiment.py`, class `Rule`): No reservation; Reactive (forecast demand, now, only when lead ≤ prep + 1); Certainty-equivalent (forecast demand, now, every forecast); Fixed proactive (forecast demand, mid-lead, p ≥ 0.5); Floor-JIT (floor, just in time, every forecast); Tuned rule (best of amounts {floor, demand, upper} × timings {now, mid, jit} × thresholds {0, 0.6, 0.8, 0.9, 0.95} on the tuning seeds, per λ); Slice-tuned rule (the same search per slice).

## 9. Compile the paper

**Overleaf:** upload `Overleaf_Source.zip` (New Project → Upload Project). The default pdfLaTeX compiler works; `main.tex` is the main document.

**Overleaf, single file:** `python scripts/build_submission.py standalone` writes `dist/Overleaf_SingleFile/`: one `main.tex` with every result, table and reference inlined, and the 8 figures as PNG files (200 dpi) in the same folder. Paste that `main.tex` into an Overleaf project and upload the PNGs next to it, not in a subfolder; nothing else is needed. The text is identical to `paper/main.pdf`; only the figures are raster images instead of vector PDFs.

**Locally:**

```sh
python scripts/build_submission.py pdf      # pdflatex + bibtex, or Tectonic if pdflatex is missing
```

## 10. Run the demo

```sh
python -m web.server        # then open http://127.0.0.1:8080
```

See the "Run the live demo" section of `README.md` for a walkthrough. A recorded demo is in `results/demo/care_demo.mp4`.

## 11. Rebuild the submission zip

```sh
python scripts/build_submission.py pdf standalone package
```

This writes `dist/Overleaf_Source.zip`, `dist/Overleaf_SingleFile/` (and its zip) and `dist/CARE_Final_Submission.zip`. The last one contains both Overleaf versions, the paper PDF, all code, models, results, this guide and the revision reports.
